# 临床试验交互分析 · teal 模板

本版本是原「Shiny临床可互动模板_图形增强版」的独立替代方案。主要目的是体验 Roche NEST / pharmaverse 的 teal 原生交互框架，保留旧版模拟数据和中心化监察思路。原目录不需要修改。

## 1. 启动

1. 双击 `teal临床模板.Rproj` 打开项目。
2. 首次尚未安装包时，在RStudio Source `install_packages.R`。现用电脑在生成时已单独安装了主要依赖；若缺少包，再执行此步骤。
3. 打开 `start.R` 并 Source，或打开 `app.R` 并 Run App。建议使用前者，它自动配置包库并在本机浏览器打开。
4. 启动后先进入网页的数据准备界面。选择 **使用模拟数据** 可立即体验，也可以上传自己的数据文件后点击 **开始分析**。日常更换项目不再要求修改 `config.R`。

包库：`%LOCALAPPDATA%/R/TealTemplates/<R主次版本>`，启动时还可读取原 ShinyTemplates 包库。安装目录和原 TFL / Shiny 代码、包库相互隔离，不自动在每次启动时安装。

## 2. 如何操作

- 上传数据、确认变量映射和分析口径后，点击 **开始分析**。顶部 **Module** 菜单会根据当前实际提供的数据集动态展示可用分析模块；完整模拟数据包含15个模块。
- 要切换项目或重新上传文件，点击 **更换数据** 返回数据准备流程。重新加载后应重新确认分析人群和参数，当前筛选、图形选择等交互状态也会重置。
- 左侧 **Active Data Summary**：查看观测数、受试者数及筛选后的规模。
- 左侧 **Filter Data**：在数据集名称右侧点击加号，选择变量、类型和值；有父子关系的数据可通过USUBJID联动。
- 各原生模块可进行分析参数选择、图形设置、查看 R code，以及按模块支持情况加入 Report。自定义模块以交互展示和DT表为主，未实现 teal 原生代码回放和报告卡片接口。
- 通用图形的 X/Y、组别、分层等选择器初始指向同一个数据集；换数据集时，应把相关选择器统一切换到相同分析记录层级，除非明确需要按连接键合并。不同粒度的数据连接会改变记录数，需结合 Active Data Summary 和图形统计表核查。
- KRI历史快照数据是独立聚合数据，刻意和受试者层数据分开。选择KRI明细行可查看指标趋势；在AE图形页面选择汇总行可钻至原始记录。

## 4. 换成真实数据

### 4.1 在网页中选择文件

在数据准备界面上传数据。ADSL是必需数据集；ADAE、ADLB（或同结构的ADRE等）、ADTTE、QUERY、KRI按需要上传。支持 `.sas7bdat`、`.xpt`、`.rds`、`.csv`、`.xlsx`（默认首个工作表）。未上传可选数据集时，相应分析页面不会启用。文件应为当前研究的数据，不需要改动R程序中的文件路径。网页单文件上传请求上限约100 MB。

### 4.2 设置变量映射

各数据集的变量映射会根据上传文件中的标准字段名及常见别名预选，用户可以从下拉框修改对应关系，或留空不使用不需要的可选字段。例如：

| 模板标准变量 | 可以选择的实际变量示例 | 含义 |
| --- | --- | --- |
| USUBJID | USUBJID | 受试者唯一编号 |
| SITEID | CENTER | 研究中心编号 |
| TRT01P | TRT01A | 治疗组；按实际分析口径选择计划或实际治疗组 |
| SAFFL | SAFFL | 安全性分析集标志 |
| AVAL | AVAL | 连续指标分析值 |

自动预选只是便利功能，必须检查含义而不仅是名称是否一致。若ADSL本身没有STUDYID列，可在网页填写研究编号；若有该列，则应正常完成映射。本模板只处理一个研究。

| 数据 | 最少需要字段（模板内部名称） |
| --- | --- |
| ADSL（必需） | STUDYID、USUBJID、SITEID、TRT01P；入组另需RANDDT；描述表可选AGE、SEX等 |
| ADAE | USUBJID、AEBODSYS、AEDECOD |
| ADLB/ADRE | USUBJID、PARAMCD、AVISIT、AVISITN、AVAL、AVALU；可附BASE、CHG、PCHG |
| ADTTE | USUBJID、PARAMCD、AVAL、AVALU、CNSR（0=事件，1=删失） |
| QUERY | USUBJID、QUERYID、OPEN_DATE、CLOSE_DATE |
| KRI | SITEID、KRI、VALUE、DEN、SNAPSHOT |

### 4.3 设置分析人群、记录、日期与类型

- 在网页的人群筛选设置中选择ADSL的标志变量及需要保留的值，例如 `SAFFL` = `Y`，或 `FASFL` = `Y`。临床子数据集会同步保留该人群中的受试者记录。若不指定人群筛选，则使用全部ADSL。
- 对ADAE、ADLB、ADTTE等子数据集，可以按变量和值选择分析记录。例如ADAE选择 `TRTEMFL` = `Y`，ADLB选择 `ANL01FL` = `Y`。必须依据项目SAP定义，不能只按示例设置。
- ADSL需要每受试者一行；临床子数据集通过STUDYID和USUBJID关联ADSL。ADLB需要每受试者/指标/访视一条分析记录；ADTTE每受试者/指标一条，并明确CNSR的编码（0为事件、1为删失）。
- 根据数据实际格式填写日期原点、文本日期格式和分析快照日期。SAS数值日期常用原点 `1960-01-01`；文本日期如 `2026-11-24` 使用 `%Y-%m-%d`。如是Excel数值日期，应配置相应原点。
- CSV按字符读取以避免受试者编号和中心编号丢失前导零，已映射的标准数值字段按分析需要转换。对于额外的连续型变量，可在网页中选择需要转换为数值类型的列，以便参与统计或绘图；标识变量不应转换为数值。

请确认全部输入和映射后点击 **开始分析**。页面中的治疗组、分析人群、子数据集筛选及日期设置适用于当前分析；这些输入不需要写回 `config.R`。分析结束，可点击 **更换数据** 重新载入其他项目。`config.R` 保留默认配置和原先的程序式接口，供维护或固定分析规则时参考。

注意：KRI表不是由本模板自动从原始记录推算生成的；应先依据正式KRI统计计划计算，再接入本页面。模拟数据有演示用风险阈值，真实上传的KRI不自动采用这些阈值；可在KRI上传区勾选“设置本项目的KRI风险阈值（可选）”，没有配置正式阈值的指标显示为“未评估”，而不是“风险正常”。真实受试者数据仅应在公司批准的本地或内部环境运行，默认监听127.0.0.1。

## 5. 程序结构

```text
teal临床可互动模板/
├── start.R                # RStudio启动（Source）
├── app.R                  # 网页数据准备及teal应用入口
├── config.R               # 默认参数及原程序式配置
├── install_packages.R     # 独立包库
├── R/
│   ├── bootstrap.R       # 包环境
│   ├── demo_data.R       # 原版模拟数据发生器
│   ├── data.R            # 数据读取、映射、teal_data和join_keys
│   ├── modules.R         # 现成teal模块及导航配置
│   ├── monitoring.R      # KRI/Query/入组/AE图形补充模块
│   └── upload.R          # 网页上传、映射、会话内分析模块
└── tests/                 # 统计及应用检查
```

主要流程：网页数据上传/模拟数据 → 变量映射及统计口径 → 数据准备与检查 → `teal.data::teal_data()`（用 `join_keys` 建立数据关系）→ `teal::modules()`（装配分析模块）→ teal原生图表和交互筛选。

相比纯Shiny，每个现成分析页面不再手写整套UI/server；设置统一筛选、数据关系和报告框架即可。对于没有标准模块的监察业务才用 `teal::module()` 补充。
